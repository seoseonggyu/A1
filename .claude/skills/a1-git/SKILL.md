# Git Commit (UE C++ / 1인 개발)

혼자 쓰는 저장소라 브랜치 전략은 없다. `main`(또는 현재 브랜치) 하나에 순서대로 쌓는다.
다만 UE 프로젝트는 코드와 `Content/`의 바이너리 에셋이 섞여 있어서, 잘못 커밋하면 되돌리기가 아주 번거롭다.
그래서 **커밋 전 확인**과 **의심스러우면 사용자에게 질문**이 이 스킬의 핵심이다.

## 1. 커밋 전에 항상 확인

```bash
git status --short
git diff --stat HEAD                 # 아직 커밋 안 된 변경량
git log --oneline -5                 # 최근 커밋 = 번호 확인용
git diff origin/main --stat          # 마지막 push 이후 누적 변경 (원격 없으면 생략)
```

이 결과를 먼저 읽고 나서 커밋 메시지를 만든다. 파일 목록을 보지 않고 메시지를 지어내지 않는다.

## 2. 제목: 번호 + 제목

- 형식: `NN. 제목` (예: `08. Enemy AI 수정`)
- 번호는 `git log -1 --pretty=%s`의 맨 앞 숫자 + 1.
- 숫자가 없거나 첫 커밋이면 `01.`부터 시작.
- 두 자리로 맞추고(`01`, `09`, `10`), 99를 넘으면 그대로 `100.`
- 번호를 건너뛰거나 되돌리지 않는다. 항상 마지막 커밋 기준.
- 제목은 이번 변경의 핵심 하나만 짧게 (40자 이내). 이모지나 서명은 넣지 않는다.

## 3. 본문: 변경점 요약

마지막 push 이후 바뀐 내용을 기준으로, 각 줄을 `- `로 시작하는 불릿으로 적는다.

- 3~6줄 정도. 파일 경로를 나열하지 말고 **의미 단위**로 묶는다.
- 어떤 클래스/에셋/시스템이 바뀌었는지 알 수 있게 이름을 넣는다.
- 코드와 에셋이 같이 바뀌었으면 둘 다 언급한다.

**예시**

```
08. Dash Ability 추가

- GA_Dash 어빌리티 추가
- ASC 태그 정리 및 쿨다운 적용
- 캐릭터 이동 속도 값 조정
- Dash 나이아가라 이펙트 에셋 추가
```

## 4. 사용자에게 반드시 물어보는 경우

아래 중 하나라도 걸리면 **커밋을 실행하지 말고** 상황을 한두 줄로 요약한 뒤
"Commit을 할까요?" 라고 묻고 답을 기다린다.

**기존 파일 수정이 클 때**
- 변경 파일 20개 이상, 또는 diff 500줄 이상
- `.uasset` / `.umap` 이 10개 이상 바뀜
- 파일 삭제·이름 변경이 포함됨 (UE는 레퍼런스가 깨질 수 있음)

**새로 추가되는 내용이 미심쩍을 때**
- 단일 파일 5MB 초과 (100MB 초과면 LFS 없이는 push 자체가 실패한다고 알려줄 것)
- 마켓플레이스/샘플 에셋처럼 통째로 들어오는 대용량 폴더
- 굳이 저장소에 없어도 되는 것: 빌드 산출물, 캐시, 로그, 스크린샷, 백업본, 개인 설정
- 키·토큰·비밀번호가 들어있을 만한 파일

**무시되어야 할 경로가 잡혔을 때**
`Binaries/`, `Intermediate/`, `Saved/`, `DerivedDataCache/`, `Build/`, `.vs/`, `*.sln`, `*.suo`
→ 커밋하지 말고 `.gitignore`에 추가할지 먼저 묻는다.

질문할 때는 그냥 예/아니오만 받지 말고, 필요하면
"전부 커밋 / 코드만 먼저 커밋 / 특정 파일 제외" 같은 선택지를 같이 제시한다.

## 5. 실행 규칙

- `git add .` 를 바로 쓰지 않는다. `git status`로 확인한 뒤 필요한 경로만 명시적으로 추가한다.
- 커밋 메시지는 `-m` 두 번(제목/본문) 또는 heredoc으로 작성한다.
- **push는 사용자가 요청했을 때만** 한다. 커밋만 요청하면 커밋에서 멈춘다.
- `push --force`, `reset --hard`, `rebase` 등 히스토리를 바꾸는 명령은 사용자가 명시적으로 시키기 전엔 쓰지 않는다.
- 커밋 후에는 `git log -1 --stat` 결과를 짧게 보여준다.
- 사용자가 요청하지 않은 파일은 수정하지 않는다.

## 6. 저장소 초기 점검 (한 번만)

`.gitattributes`에 LFS 설정이 없는데 `Content/`에 바이너리 에셋이 있으면 한 번 알려준다.

```
*.uasset filter=lfs diff=lfs merge=lfs -text
*.umap   filter=lfs diff=lfs merge=lfs -text
```

## 7. Commit 후
- Commit 후에는 작성한 제목과 내용들을 사용자에게 알려준다.

이미 설정돼 있거나 사용자가 필요 없다고 하면 다시 언급하지 않는다.
